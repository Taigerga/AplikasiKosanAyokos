=== PENJELASAN TEORI: KOMPONEN YANG SEHARUSNYA MENGGUNAKAN REST API DI LARAVEL ===
*Catatan: Laravel belum merilis versi 13 (versi stabil terbaru per 2026 adalah Laravel 12), prinsip REST API berikut berlaku umum untuk Laravel modern:*

1. **API Routes (routes/api.php)**
   - Semua endpoint yang menyediakan data JSON untuk konsumsi eksternal (mobile app, SPA, integrasi pihak ketiga)
   - Wajib menggunakan standar HTTP method REST: GET (ambil data), POST (buat data), PUT/PATCH (update data), DELETE (hapus data)
   - Menggunakan `Route::apiResource()` untuk CRUD standar otomatis

2. **API Controllers (app/Http/Controllers/API/)**
   - Controller yang mengembalikan response JSON, bukan view Blade
   - Tidak menggunakan session auth, melainkan token-based auth (Laravel Sanctum/Passport)
   - Menangani logic bisnis untuk endpoint API

3. **API Resources**
   - Sebaiknya menggunakan Laravel API Resources untuk memformat response JSON secara konsisten

4. **Authentication API**
   - Menggunakan middleware `auth:sanctum` untuk proteksi endpoint API
   - Tidak mencampur dengan session auth (khusus web routes)

5. **Yang TIDAK Perlu REST API:**
   - Web routes (routes/web.php) untuk server-side rendering (Blade views)
   - Controllers yang mengembalikan Blade views
   - Blade template files (resources/views/)
   - Database migrations/seeders/factories (hanya struktur data, tidak terkait API)

=== CARA MENGECEK REST API MENGGUNAKAN POSTMAN ===

1. **PERSIAPAN SEBELUM TESTING**
   - Pastikan Laravel server berjalan: `php artisan serve`
   - Buka Postman aplikasi
   - Base URL: http://127.0.0.1:8000 (atau sesuai port server)

2. **LOGIN UNTUK MENDAPATKAN TOKEN (AUTH:SANCTUM)**
   
   Method: POST
   URL: http://127.0.0.1:8000/api/auth/login
   
   Headers:
   - Content-Type: application/json
   - Accept: application/json
   
   Body (raw JSON):
   ```json
   {
       "email": "email_user@example.com",
       "password": "password_user",
       "role": "penghuni"  // atau "pemilik" atau "admin"
   }
   ```
   
   Response sukses akan mengembalikan token:
   ```json
   {
       "success": true,
       "user": {...},
       "token": "1|abc123...",
       "role": "penghuni"
   }
   ```
   
   COPY token untuk digunakan di request selanjutnya.

3. **CARA MENGGUNAKAN TOKEN DI POSTMAN**
   
   Untuk endpoint yang diproteksi (butuh auth:sanctum):
   
   Headers tambahan:
   - Authorization: Bearer 1|abc123... (token dari login)
   
   Atau di Postman:
   - Tab "Authorization"
   - Type: Bearer Token
   - Token: (paste token di sini)

5. **HTTP METHODS & ENDPOINTS LENGKAP**

   - GET    = Ambil data (index, show)
   - POST   = Buat data baru (store, login, register)
   - PUT    = Update seluruh data (update)
   - PATCH  = Update sebagian data
   - DELETE = Hapus data (destroy)

   Contoh:
   - GET    /api/kos           = List semua kos
   - GET    /api/kos/1         = Detail kos ID 1
   - POST   /api/kos           = Buat kos baru
   - PUT    /api/kos/1         = Update kos ID 1
   - DELETE /api/kos/1         = Hapus kos ID 1

6. **CEK STATUS RESPONSE**
   
   - 200 OK = Sukses GET/PUT
   - 201 Created = Sukses POST (data baru dibuat)
   - 400 Bad Request = Request salah
   - 401 Unauthorized = Token tidak valid/expired
   - 403 Forbidden = Tidak punya akses
   - 404 Not Found = Data tidak ditemukan
   - 422 Unprocessable Entity = Validasi gagal

7. **LOGOUT**
   
   Method: POST
   URL: http://127.0.0.1:8000/api/auth/logout
   Headers: Authorization: Bearer {token}
   
   Response:
   ```json
   {
       "success": true,
       "message": "Logged out successfully"
   }
   ```

8. **TIPS DEBUGGING DI POSTMAN**
   
   - Selalu cek tab "Body" untuk response JSON
   - Cek tab "Headers" untuk melihat response headers
   - Gunakan tab "Console" (Postman Console) untuk melihat detail request/response
   - Pastikan Content-Type: application/json untuk request POST/PUT
   - Jika error 401, cek token sudah benar dan belum expired
   - Jika error 422, cek response body untuk pesan validasi error

   ```json
   {

       }
   ```
   ```json
   }
   ```
