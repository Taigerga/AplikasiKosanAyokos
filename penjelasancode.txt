---
1. GAMBARAN UMUM
---
Aplikasi Ayokos adalah platform web berbasis Laravel yang dirancang untuk 
memfasilitasi pencarian, pemesanan, dan manajemen kos (kost/kontrakan) di 
Indonesia. Sistem ini mendukung dua jenis pengguna utama: Penghuni (pencari 
kos) dan Pemilik (pemilik properti kos). Aplikasi dilengkapi dengan fitur 
pencarian canggih, sistem booking, manajemen pembayaran, notifikasi real-time, 
dan analisis data.

Teknologi Utama:
- Framework: Laravel (PHP)
- Frontend: Blade Templates, Tailwind CSS, Font Awesome
- Database: MySQL/MariaDB (relasional)
- Library Spesifik: Leaflet.js (pemetaan interaktif)
- Architecture: MVC (Model-View-Controller) + Repository Pattern

---
2. SISTEM AUTHENTICATION & AUTHORIZATION
---

2.1. Struktur Autentikasi Multi-Guard:
- Sistem menggunakan dua guard terpisah: 'penghuni' dan 'pemilik'
- Masing-masing guard memiliki provider model independen
- Session-based authentication dengan opsi "Remember Me"
- Password di-hash menggunakan algoritma bcrypt/Laravel Hash

2.2. Alur Login:
- User memilih role (penghuni/pemilik) pada form login
- Validasi kredensial terhadap tabel masing-masing (penghuni/pemilik)
- Regenerasi session ID untuk keamanan
- Redirect ke dashboard berdasarkan role

2.3. Proses Registrasi:
- Validasi umur minimum 17 tahun (persyaratan legal)
- Pengecekan unique username per role
- Upload foto profil opsional (maksimal 2MB)
- Tiga jenis user dalam sistem:
  * Penghuni: Pencari dan penyewa kos
  * Pemilik: Pemilik properti kos (bisa memiliki banyak kos)
  * Admin/Super: (implisit melalui model User)

2.4. Middleware Proteksi:
- Route middleware 'auth' untuk area terproteksi
- Role-based access control melalui middleware 'role'
- Semua route penghuni dan pemilik dilindungi autentikasi

4. STRUKTUR DATABASE & MODEL ELOQUENT
---

4.1. Tabel Utama & Relasi:

Tabel: penghuni (PK: id_penghuni)
- Relasi: hasMany(KontrakSewa) - satu penghuni bisa punya banyak kontrak
- Relasi: hasMany(Pembayaran) - riwayat pembayaran
- Relasi: hasMany(Review) - ulasan yang dibuat
- Relasi: morphMany(Notification) - notifikasi terkait

Tabel: pemilik (PK: id_pemilik)
- Relasi: hasMany(Kos) - satu pemilik bisa punya banyak kos
- Relasi: morphMany(Notification)
- Field utama: nama, no_hp, email, username, password, nama_bank, nomor_rekening

Tabel: kos (PK: id_kos) [FK: id_pemilik]
- Relasi: belongsTo(Pemilik) - milik siapa
- Relasi: hasMany(Kamar) - punya banyak kamar
- Relasi: belongsToMany(Fasilitas) - pivot melalui kos_fasilitas
- Relasi: hasMany(KontrakSewa)
- Relasi: hasMany(Review)
- Field utama: nama_kos, alamat, kecamatan, kota, provinsi, jenis_kos (putra/putri/campur)
- Scope: scopeAktif(), scopeDenganKamarTersedia()

Tabel: kamar (PK: id_kamar) [FK: id_kos]
- Relasi: belongsTo(Kos)
- Relasi: hasMany(KontrakSewa)
- Accessor: getFotoKamarUrlAttribute() - normalisasi path foto
- Field utama: nomor_kamar, tipe_kamar, harga, kapasitas, fasilitas_kamar (JSON)
- Status: tersedia/terisi

Tabel: kontrak_sewa (PK: id_kontrak) [FK: id_penghuni, id_kos, id_kamar]
- Relasi: belongsTo(Penghuni, Kos, Kamar)
- Relasi: hasMany(Pembayaran) - pembayaran terkait kontrak ini
- Relasi: hasMany(Review) - review dari kontrak ini
- Field utama: tanggal_daftar, tanggal_mulai, tanggal_selesai, durasi_sewa
- Status: pending/ditolak/aktif/selesai
- Boot event: otomatis ubah kamar jadi tersedia saat status=selesai

Tabel: pembayaran (PK: id_pembayaran) [FK: id_kontrak, id_penghuni]
- Relasi: belongsTo(KontrakSewa), belongsTo(Penghuni)
- Field utama: bulan_tahun, jumlah, status_pembayaran
- Status: belum/pending/lunas/terlambat
- Scope: scopeLunas(), scopePending(), scopeBelumBayar()

Tabel: review (PK: id_review) [FK: id_kos, id_penghuni, id_kontrak]
- Relasi: belongsTo(Kos, Penghuni, KontrakSewa)
- Field utama: rating (1-5), komentar, foto_review
- Validation: rating harus 1-5
- Accessor: getStarRatingAttribute() untuk visual bintang

Tabel: fasilitas (PK: id_fasilitas)
- Field: nama_fasilitas, kategori, icon
- Relasi: belongsToMany(Kos)

Tabel: notifications (PK: id_notifikasi)
- Polymorphic: user_type + id_user
- Field: judul, pesan, tipe, dibaca, link
- Scope: scopeUnread(), scopeForUserType(), scopeForUser()

4.2. Database Design Principles:
- Nama tabel singular (penghuni, pemilik) dan plural (fasilitas)
- Foreign key mengikuti konvensi: id_[nama_tabel]
- Composite foreign key di relasi pivot: kos_fasilitas
- Soft delete tidak digunakan (delete permanen)
- Timestamps standar: created_at, updated_at
- Casts untuk JSON: fasilitas_kamar di tabel kamar

5. ALUR DATA & INTERAKSI SISTEM
---

5.1. Alur Pencarian Kos (Penghuni):
  1. Penghuni akses /kos (GET)
  2. Controller KosController@index memproses query parameters
  3. Eloquent query: where('status_kos', 'aktif')
  4. Filter tambahan: search, jenis_kos, kota, tipe_sewa, ketersediaan
  5. Eager loading: with(['fasilitas', 'reviews']) untuk performa
  6. View: public/kos/index.blade.php render hasil pencarian
  7. Pagination otomatis Laravel (paginate)

5.2. Alur Booking Kontrak (Penghuni):
  1. Penghuni klik "Sewa" di detail kos
  2. KontrakController@create: cek kamar tersedia, ambil data
  3. POST ke /kontrak (store)
  4. Validasi data penghuni + ketersediaan kamar
  5. Buat record KontrakSewa dengan status = 'pending'
  6. Trigger event: kirim notifikasi ke pemilik (async)
  7. Redirect ke detail kontrak dengan status pending
  8. Pemilik terima notifikasi (database + email)

5.3. Alur Persetujuan Kontrak (Pemilik):
  1. Pemilik masuk dashboard /pemilik/dashboard
  2. Lihat list kontrak pending di sidebar
  3. Click "Terima" atau "Tolak" di KontrakController
  4. Update status_kontrak = 'aktif' atau 'ditolak'
  5. Trigger notification: kirim email ke penghuni
  6. Jika diterima: penghuni bisa bayar (opsional)
  7. Auto-update kamar status saat kontrak selesai

5.4. Alur Pembayaran (Penghuni - ke Pemilik):
  1. Penghuni akses /penghuni/pembayaran/create
  2. Pilih kontrak aktif yang ingin dibayar
  3. Input: bulan_tahun, nominal, metode pembayaran
  4. POST /pembayaran/store
  5. Buat record Pembayaran (status = 'pending')
  6. Upload bukti bayar (file ke storage/app/public/)
  7. Redirect ke detail pembayaran
  8. Pemilik verifikasi (approve/reject)
  9. Update status_pembayaran = 'lunas' atau 'belum'
  10. Notifikasi balik ke penghuni

5.5. Alur Review (Penghuni):
  1. Setelah kontrak selesai, penghuni bisa review
  2. POST /reviews/store dengan rating (1-5) + komentar
  3. Validasi: rating validasi range 1-5
  4. Update total review di Kos (via relasi hasMany)
  5. Hitung ulang rata-rata rating (accessor)
  6. Tampil di halaman detail Kos

6. FITUR UTAMA

- Pencarian teks bebas (nama, alamat, kecamatan, kota)

- Filter lokasi (kota)
- Filter ketersediaan kamar
- Filter tipe sewa (bulanan/tahunan)
- Sorting otomatis berdasarkan relevansi
- Pagination dengan 10-20 item per halaman

6.2. Sistem Booking Kontrak:
- Form booking berbasis kontrak sewa
- Validasi real-time ketersediaan kamar
- Durasi sewa otomatis (dari tanggal mulai - selesai)
- Status flow: pending → aktif/ditolak → selesai
- Auto-aktivasi saat pemilik setujui
- Auto-expire jika tidak dibayar dalam batas waktu

6.3. Manajemen Pembayaran:
- Multi-pembayaran per kontrak (per bulan)\n- Upload bukti transfer (file gambar)
- Validasi bukti oleh pemilik
- Status tracking: belum → pending → lunas/terlambat
